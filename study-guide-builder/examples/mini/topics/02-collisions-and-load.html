Big idea

Collisions are not a bug, they are a certainty. A hash table works well when you (1) have a rule for sharing a slot and (2) keep the table from getting too crowded.

Strategy 1: separate chaining

Let every bucket hold a small list. A key that hashes to bucket i goes onto bucket i's list. To search, hash to the bucket, then scan that one short list.

Real-life example

Mailboxes in an apartment building. Everyone whose surname starts with “S” shares one pigeonhole, and mail for that group is stacked in it. You go straight to the “S” hole, then flick through the few letters inside.

Strategy 2: open addressing (linear probing)

Here every slot holds at most one key. If slot h(k) is taken, try the next slot, then the next (wrapping around), until you find a free one. Searching follows the same path.

m = 7, h(k) = k mod 7, linear probing. Insert 10, 25, 31, 44, 17 in that order.
  1. 10 → h = 3. Slot 3 is free. Place it. Table: slot 3 = 10.
  2. 25 → h = 4. Slot 4 is free. Place it. Slots 3, 4 = 10, 25.
  3. 31 → h = 3, taken by 10. Probe slot 4, taken by 25. Probe slot 5, free. Place it. Slots 3, 4, 5 = 10, 25, 31.
  4. 44 → h = 2. Slot 2 is free. Place it. Slots 2, 3, 4, 5 are now all occupied.
  5. 17 → h = 3, taken. Probe 4, 5 (taken), then slot 6, free. Place it. The occupied run is now slots 2 to 6.
  6. Observe: one long block of full slots has formed. Any key hashing anywhere inside it has to walk to the end. This is primary clustering.
In the table above, you search for key 24 (h = 3). It is not stored. How many slots do you check before you can say “not found”, and why does it take so long?

You check slots 3, 4, 5, 6, and then 0, which is empty. That is 5 probes, because the cluster forces you to walk all the way to the first empty slot. An empty slot is the signal that the key cannot be further along. Clusters make failed searches expensive.

The load factor and resizing

The load factor is α = n / m. It is the single number that predicts speed:

Separate chainingLinear probing
Can α exceed 1?YesNo (table would be full)
Where collisions goInto the bucket's listInto the next free slot
Typical resize thresholdα ≈ 1α ≈ 0.5 to 0.7
WeaknessExtra memory for list nodesClustering as α grows

When α passes the threshold, allocate a bigger array (often double) and rehash every key into it. You cannot just copy keys over: the index is h(k) mod m, and m has changed.

Memory trick

Chaining = “pile up”, probing = “shuffle along”. And for the load factor, think of a restaurant: once it is more than about two-thirds full, finding a free table takes much longer.

Watch out

Deleting from an open-addressing table is subtle: simply emptying a slot breaks the probe path of keys stored after it. Real implementations mark the slot with a “deleted” tombstone instead.
